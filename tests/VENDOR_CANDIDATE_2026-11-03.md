## 功能

- `vendors/` 可由管理員手動隱藏及恢復，常用／隱藏／全部清單皆可搜尋。
- `is_hidden` 與 `is_active` 分開；只有一個新增欄位的增量候選，不改 UUID、外鍵、RLS 或資料內容。現有停用語意保留。恢復隱藏不會順便啟用停用廠商。
- `calculator/` 同樣提供範圍切換，隱藏及停用廠商歷史不再因主檔查詢而不可達；`board/` 常用建貨件選單省略隱藏廠商，歷史貨件仍可查。既有手動輸入／編輯可以使用隱藏廠商。
- 三處廠商顯示按現有 code 自然排序；沒有代碼者排後。分頁仍按 UUID，顯示排序不影響身份。
- `vendors/` 管理員可選取本機 Excel 的「價格清單」預覽。A–O 欄名必須完全符合；只讀取，不上傳，不呼叫匯入 RPC，不儲存 local/session storage，關閉／清除即移除預覽。
- 預覽保留全部來源欄位、null、原單位、底價與停用歷史。只以完整 code＋公司名匹配 UUID；未匹配／多匹配顯示候選供人工核對，沒有自動選取或正式寫入步驟。

## 正式使用前

不能直接把根目錄的所有 migration 當完整 baseline 重播。新增 `supabase/migrations/20261103041015_add_vendor_visibility.sql` 只適用既有 vendors 表；已在重建後的拋棄式 PGlite 套用並驗證。發布新頁面前須另行審核及授權套用這一個增量。此次沒有套任何遠端 schema。

正式價格匯入仍需確認：

1. 私人來源的當次版本、筆數與每列來源 ID；私人資料不得進公開 repo。
2. 逐列公司 code＋name 與現有 UUID／新公司建立決策；號碼撞到但名字不同不能合併，缺代碼不得猜。
3. 產品 UUID 對應、原文留存、同品各期歷史及停用狀態；來源 ID 不能當產品 UUID。
4. 未知價格保持 null，但正式表 unit_price 非空，需要另行定義待確認資料位置，不能填 0 通過。
5. 原表未註單位及桶／包／批等單位的計價行為；現有貨件按公斤計價，不能強制套 kg。
6. 每批底價及條件是否適合 minimum_charge；沒有底價保持 null，不補固定數字。
7. 真正生效日及歷史期間；收到日不得代用，空日期會被現有價格選擇器當作無起始限制，故不產生可執行價格寫入。
8. 最新正式資料重讀核對、匯入交易／重送防重／衝突保護、來源追溯與權限方案均待後續，不使用本次預覽覆蓋正式資料。
